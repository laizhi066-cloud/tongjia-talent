# B/C 端设计约定

> 本文件记录同佳天赋的跨端视觉基线。工程硬性约束以 [AGENTS.md](../AGENTS.md) 与 [docs/CONVENTIONS.md](../docs/CONVENTIONS.md) 为准；C 端页面、认证和主题实现见 [CLIENT-PORTAL.md](../docs/CLIENT-PORTAL.md)；当前页面清单见 [STATUS.md](../docs/STATUS.md)。

## 设计目标

- B 端是天赋业务的唯一后台：平台会员、天赋规则、报告接收与发布、培养计划审核、机构与授权，外加用户 / 角色 / 菜单、站点与微信配置、健康 / 在线 / 错误监控。
- C 端是“首页 + 我的”双 Tab 门户，登录后以报告对象（本人 / 子女）为组织单位承载报告、要素解读和培养计划。
- 品牌名称、Logo、主色和站点默认主题只来自唯一的 `site_config`，不含多站点、多品牌或行业主题。
- 视觉低密度、可扫读；不预置演示业务内容或虚构数据，空态必须说明状态并给出下一步。

## B 端

- 技术栈为 Nuxt 4 + Vue 3，Naive UI 按需 import，图标统一使用 `@vicons/ionicons5`。
- 列表页优先使用 `AdminListPage` + `NDataTable` + `AdminPagination`；页面专属组件就近放在页面目录，全局组件不得承载业务逻辑。
- 侧边栏是主导航，按业务链路分组：平台会员 / 天赋工作台 / 服务商授权 / 培养计划审核、「会员管理」（机构端）、「天赋规则」、「天赋报告」、「系统管理」、「运行监控」。不要为同一能力叠加顶栏 Tab。
- 天赋业务列表只展示决策所需字段（名称、状态、更新时间、关联对象）和必要操作；创建 / 更新审计字段与内部 ID 收进「查看详情」弹窗。
- 六个及以上短字段的表单使用宽屏两列栅格，长文本、上传和动态内容占整行；不要堆成窄单列。
- 桌面端保证筛选、主操作、表格和分页的稳定布局；窄屏允许表格内部横向滚动，不让整页被列宽撑破。
- 危险操作（删除、停用机构、撤回报告、踢出在线会话、清空错误、注销）必须使用破坏性样式 + 二次确认，文案说清影响对象和不可恢复性。
- 报告状态用统一标签：待发布 / 已发布 / 已撤回 / 异常；异常项要能一眼看到原因入口（报告接收、匹配失败说明）。

## C 端

- 技术栈为 uni-app（H5 + 微信小程序）+ Vue 3 + Pinia，基础控件使用 Wot UI。
- 固定双 Tab 由 `PortalTabbar`（内部 `wd-tabbar`）自绘：首页、我的；`pages.json` 不注册原生业务 TabBar。
- `pages/index/index.vue` 与 `pages/me/me.vue` 仅组合模块组件和导航动作；展示与状态逻辑置于 `apps/client/src/modules/foundation-portal/`。
- 首页结构：微信原生导航（标题「首页」）→ `TalentHomeContent` → `PortalTabbar`。游客看到品牌欢迎与登录入口；登录后看到报告对象条（`PortalObjectBar`，多个档案时才显示）、报告卡与四宫格入口。主栏不再有品牌栏，`PortalBrandHeader` 已移除。
- 「我的」= 账户卡（整卡可点进资料）+ 报告对象切换 + 协议 / 关于 / 注销 / 退出；不提供外观开关。
- 报告页层级：列表 → 总览（封面 + 分册开放状态 + PDF） → 目录（`wd-search` + `wd-tabs`） → 条目正文（阅读进度）。目录与条目只在对应分册开放时可进入。
- 使用内联 SVG 或已有 Wot 图标，不使用 Emoji 作为 UI 图标。
- 视觉形态采用小程序的单列信息流：顶部品牌区、独立卡片、分组单元格、固定底部导航。不要把桌面工具栏、侧边栏、宽表格或 B 端卡片密度搬到移动端。
- 未登录、微信未配置、接口失败、空报告时避免白屏，必须给出可理解的说明与重试 / 登录入口。

## 主题令牌

- 颜色、阴影、圆角均以 `--foundation-*` CSS 变量表达，默认值使用 OKLCH；组件内不得硬编码品牌色或行业文案。
- C 端 `useSiteStore` 把唯一站点的 `primaryColor` 与 `themeMode` 派生为门户令牌，并映射给 Wot UI token。
- C 端**不提供**用户侧外观切换：只跟随后台站点配置的浅色 / 深色 / 跟随系统。B 端后台的亮暗是管理员本机偏好，不回写站点配置，也不影响 C 端。
- 字号统一使用 px（375pt 基准，750 设计稿数值 ÷2），只有发丝线保留 `1rpx`；字号走 `--fs-*` 令牌，不写死数值。

## 布局与交互

- 所有可点击主控件最小触控高度为 44px；图标按钮提供 `aria-label`，底部导航使用 Wot UI 的当前选中态。
- 明暗模式下正文、边框、焦点态都必须可读；H5 提供 `:focus-visible`，全局遵从 `prefers-reduced-motion`。
- 页面根禁止横向溢出；固定底部导航或底部面板必须为安全区预留空间，不能遮挡内容。
- 表单必须有清晰 label、客户端校验、保存 loading 与防重复提交。权限不足或认证缺失时，提供明确状态或引导。
- 空态不是留白：说明当前状态、给出可执行下一步，不把业务功能缺失伪装成加载失败。错误态保留重试或返回入口，不能只输出技术错误。

## 视觉 QA 基线

交付前至少检查：

- 375px 宽度无横向滚动，首页 / 我的均可到达，底部双 Tab 不遮挡内容。
- 站点浅色、深色、跟随系统三种模式均可读，切换后刷新仍正确；C 端没有外观开关残留。
- 站点品牌更新后不残留旧品牌或多站点文案。
- 游客、本人报告、子女报告、无报告四种首页状态都有明确表达。
- 报告列表 / 总览 / 目录 / 条目在未登录、无权限、分册未开放、PDF 缺失时都有可理解的状态。
- 微信登录、手机号授权、H5 账号密码登录、资料编辑、隐私 / 协议 / 关于、注销和退出在对应端显示清晰状态。
