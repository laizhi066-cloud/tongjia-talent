## 0. 结论速览

| 问题 | 结论 |
| --- | --- |
| 当前架构是否满足 PRD | **底座满足，天赋业务层不满足**。单实例单 PocketBase、RBAC、审计、上传、PDF 代理、微信登录等 Foundation 能力全部可复用（BR-01 无冲突）；但天赋业务域（会员模型、报告快照、培育建议、培养方向）与 PRD 口径差异是**重建级**，不是补丁级 |
| 复用率评估 | Foundation 底座 ≈ 全量复用；现有 `talent_*` 层约 **20%–30% 可参考复用**（报告生命周期、匹配、同步幂等、进度、CSV 导入导出的实现思路），集合与页面主体需按 PRD §8 重建模 |
| 开发策略 | 新建分支，保留 Foundation 底座，按 PRD 重建 `talent_*` 业务层；旧口径（机构 / 服务商 / 培养计划 / 内容库 / AI / 报告接收列表）代码与菜单**删除**，不做隐藏 |
| 工作量 | PRD 对应报价 40 人天（后台 36,000 + C 端 12,000）。按本计划里程碑实估 **48–53 人天（含缓冲）**；单人 ≈ 9–10 周，双人（B 端 + C 端并行）≈ **5–6 周** |
| 最高风险 | ① PRD 为评审稿，5 个待定项未确认；② PRD 与报价功能清单存在验收口径二义性；③ 外部接口（基因查询 / 建议同步）契约完全未定；④ 文库 158 项数据仅有男 0 岁库 xlsx，性别 / 年龄分库数据不全 |

**一句话**：现有工程是合格的「地基 + 一栋旧楼」，PRD 要的是「同一地基上重盖一栋新楼」——地基不动，楼上重建。

## 1. PRD 解读要点

### 1.1 商务与范围基线

- 两端合计 48,000 元：后台管理（6 一级分组 / 11 二级菜单）36,000 + C 端小程序（4 主栏 + 15 二级页）12,000。
- **明确排除**（PRD 3.2）：机构 / 代理商 / 服务商、培养计划提交与审核、内容库与培育内容、报告接收列表、跟进单 / 认领 / 转交、AI 辅助建议、多租户与站点切换、平台参数、支付与订单，页面不得出现入口。
- 平台定位：只做**同步、配置、发布与展示**，不生产报告与建议正文。

### 1.2 核心业务闭环

```
后台建档（家长+子女） → 主动查询（手机号+身份证） → 外部同步基因报告（一人一份、六册、可能增量分册）
→ 后台发布（冻结快照：要素/注解/分册/方向命中） → C 端阅读（分册/要素/建议）
→ 家长选方向与档位（≤3，可自填） → 后台回溯（版本/日志/归并）
↘ 外部按周期（4 个月）推送培育建议 → 与报告联动发布/撤回
```

### 1.3 14 条业务规则（BR）归类

| 类别 | 规则 | 工程含义 |
| --- | --- | --- |
| 模型 | BR-02 一人一份、BR-03 发布即冻结、BR-05 增量分册、BR-06 建议与报告同发、BR-07 建议按周期版本化 | 需要唯一键约束、不可变快照、版本历史与状态联动设计 |
| 匹配 | BR-08 级序命中排序、BR-09 0 命中可选 | 方向命中算法（级序 ≥，降序 + 平手规则），与现有加权达成度算法**完全不同** |
| 展示 | BR-04 固定六册、BR-10 撤回口径、BR-12 编码不外露 | 六册常量、三态状态机、C 端文案层去编码 |
| 合规 | BR-11 敏感信息、BR-13 列表规范 | 身份证加密存储 + 全号授权审计、18 位与生日一致性校验、分页 20 条 |

### 1.4 PRD 自带的待办

- 第 13.1 节：必须补齐 6 项（RBAC 落库、真实第三方接口、PDF 渲染水印时效、身份证加密、服务端分页、移除原型能力）——正是本计划的主体工作。
- 第 13.2 / 13.3 节：5 个待确认口径 + 4 个待定项，见 §8 风险表。

### 3.1 现状中「看似有、口径不同」的关键点（避免误判）

1. **报告状态机**：现有 `pending_publish / published / retracted / error` 四态，PRD 只要三态（error 归因移到查询状态机）。
2. **发布冻结**：现有发布 = 勾选分册开放 + 内容生成时固化，无「方向命中快照」也无「版本历史 + 重新发布新版本」。
3. **一人一份**：现有一人可多份报告（复测概念），PRD 明确移除复测（13.2 待确认第 3 条）。
4. **匹配算法**：现有加权达成度（80/60 阈值）vs PRD 命中条数排序（BR-08）——不可复用，需新写。
5. **C 端判据**：现有首页用「基因报告已同步」算可读册数、报告页用「已发布」判读，两套判据（原型修改方案-2026-11-14 已在原型侧修复，正式版必须单一判据 `reportView`）。

## 4. 架构评估

### 4.1 满足项（无需变更）

- 单实例单 PocketBase、Nitro 唯一服务端、统一文件 URL —— 与 BR-01 完全一致。
- RBAC 菜单 + 接口独立鉴权、`withOperLog` 审计 —— 满足 §2 / §10。
- 微信小程序 + H5 双端 uni-app、主题令牌、安全区 —— 满足 §11。
- 部署 / 备份 / 回滚 / 健康检查体系 —— 满足运维要求。

### 4.2 需要扩展的架构点

| 扩展点 | 方案要点 |
| --- | --- |
| 身份证加密与授权 | `crypto.ts` 增加字段级加解密工具；全号查看走独立权限码 + `oper_logs` 留痕；列表默认前4+后4 |
| 报告快照 | 主表 JSON 字段（`factorSnapshot / volumeSnapshot / directionSnapshot / selections / versions`）——快照只读、整份取出，不建子表；`snapshotVersion` 自增 |
| 一人一份约束 | `talent_gene_reports` 以 `subject_type + subject_id` 唯一；同步走「刷新状态不重复建档」（BR-02） |
| 建议版本化 | `talent_advice_versions`（当前生效唯一）+ `talent_advice_docs`（version 外键）；接收新一版 = 事务内归档旧版 |
| 主动查询调度 | 复用 scheduler 模式：查询队列 + 重试退避 + 归因（未出结果/信息不一致/接口异常）→ 写查询状态机 |
| PDF 水印与渲染 | 代理链路已有；渲染用服务端模板（先代理转发 + 水印页，排版增值报告迭代增强）；下载留痕写日志 |

### 4.4 API 设计映射（PRD §9 → Nitro 路由）

PRD 建议路径与现有工程约定（`/api/admin/talent/*`、`/api/client/talent/*`、Zod + `validateBody` + RBAC + `withOperLog` + `success()`）天然一致，直接按 PRD §9 表落路由；新增：

- `POST /api/admin/talent/advice/versions`（接收新一版，归档旧版）

- `GET /api/client/talent/summary / directions / advice / children`，`POST /api/client/talent/selections`
- integrations：`POST /api/integrations/talent/advice`（建议回传，幂等）

## 5. 里程碑与排期

> 估算按单人熟练开发计；双人并行时 C 端（M7）与 B 端 M2–M6 并行。依赖外部接口的部分（M8）用 Mock 适配层先行，不阻塞主链路。

### M0 · 基线与决策（1–2 人天）｜阻塞全部

**内容**

4. 确认文库数据全量交付（158 项 × 性别/年龄分库 × 12 槽位文案；当前仅男 0 岁 xlsx + 样本 docx）；

**出口**：PRD 定稿、验收依据唯一、接口契约草案、密钥轮换完成。

### M1 · 数据模型与规则域（5–6 人天）

**内容**：§4.3 全部新集合 schema、`shared/types/`、`setup.mjs`（仅新库）+ `sync-talent.mjs`（存量幂等）改造；文库种子脚本（解析 `天赋培育开发建议文库数据库（男0）.xlsx` 与样本 docx → 158 要素 + 632 注解）；分级与固定注解页（两页签 + 导入/模板/导出，复用 CSV 模式）；潜质要素页（只读 + 分库切换 + 同步 + 12 槽位文案弹层）。

**出口**：AC-ADM-04 / AC-ADM-05 全过；新库 `env:setup` 烟测通过；`talent:sync` 幂等重跑无副作用。

### M2 · 会员域（4–5 人天）

**内容**：`talent_parents/talent_children` + 身份证加密 / 脱敏 / 全号授权审计；会员 CRUD、子女就地编辑（18 位 + 生日一致性校验）、解绑二次确认、新建会员（家长 + 多子女）、主动查询触发与查询状态机。

**出口**：AC-ADM-02 全过；C 端数据归属校验（解绑后不可见）用 API 测试证明。

### M3 · 报告域（7–8 人天）｜依赖 M1（注解/分级）、M4（方向命中预览）

**内容**：`talent_gene_reports` 一人一份同步（增量分册计算 = 外部已出 − 已发布）；`talent_reports` 快照三件套 + 版本历史；发布（勾选六册 + 方向命中预览 + 冻结）、撤回、恢复、补发（只追加新增册）；一键同步全部（预演三类人数 + 逐人明细 + 日志）；报告详情 4 页签（含匹配天赋「发布时 vs 当前配置」对照）。

**出口**：AC-ADM-06 全过；快照不可变性测试（改配置 → 历史报告不变）。

### M4 · 方向与档位域（4–5 人天）｜可与 M3 并行启动

**内容**：`talent_directions/talent_tiers`；配置弹层（文库 158 项多选 + 逐项要求分级 + 档位子集 + 默认档位，无权重不校验 100）；4 预置档位维护；命中算法（BR-08：级序 ≥ 计 1 条，命中数降序 → 命中率 → 配置条数 → 编码）；删除保护（被报告引用只可停用）；自定义方向待归并入口（PRD 13.4，建议放方向页页签）。

**出口**：AC-ADM-03 全过；命中排序单测覆盖平手规则。

### M5 · 建议域（4–5 人天）

**内容**：`talent_advice_versions/docs`；接收新一版（选同步日期 → 新版本 + 旧版归档）；发布 / 撤回（仅当前版）；版本历史只读 + 回到当前生效版；建议书四段查看；15 列列表 + 操作列固定；与报告同发联动（BR-06：报告发布/恢复 → 当前周期建议置已发布；报告不可读 → 建议不可见）。

**出口**：AC-ADM-07 全过；联动状态机测试（撤回报告 → C 端建议不可见）。

### M6 · 工作台 + 系统管理 + 菜单重组（3–4 人天）

**内容**：菜单树重排为 PRD 6 组 11 菜单（setup + sync 种子）；删除旧口径页面 / API / 集合 / 菜单与机构端路由；工作台 4 指标卡 + 最近操作 6 条；系统管理 4 页对 PRD 验收（用户 / 菜单含一级分组页签 / 角色 / 操作日志）；三个角色初始化（平台运营管理员 / 报告审核员 / 规则配置员）与权限码矩阵。

**出口**：AC-ADM-01 / AC-ADM-08 全过；全站搜索无旧口径入口残留（PRD 3.2 检查）。

### M7 · C 端小程序（10–12 人天）｜B 端 M2–M6 期间并行

### M8 · 外部对接与 PDF（4–5 人天）｜契约到位后替换 Mock

**内容**：基因查询第三方 client（按手机号 + 身份证哈希拉取，重试退避 + 三类归因 + 告警）；建议回传 integrations 接口（幂等键 + 版本归档事务）；PDF 服务端渲染（六册模板 + 水印：姓名+手机尾号+报告编号）+ 时效地址 + 下载留痕；同步配置（密钥、周期）入加密配置。

**出口**：联调环境全链路（建档 → 查询 → 同步 → 发布 → 阅读 → 选方向 → 建议周期）；幂等重放无脏数据。

### M9 · 质量与验收（5–6 人天）

**内容**：单测补齐（状态机 / 快照 / 命中 / 加密 / 权限）；E2E 重写（B 端主链 + C 端主链 + 状态文案矩阵）；性能（后台列表 ≤2s@1000 条、C 端首屏 ≤1.5s、分册按需加载）；文档同步（ARCHITECTURE / API / CLIENT-PORTAL / TALENT-LOCAL / STATUS）；生产部署演练 + 备份回滚验证；对照 PRD §12 总表逐项打勾并留证据。

**出口**：门禁全绿 + 客户验收演示通过。

## 6. 测试与验收策略

1. **单元层**：状态机（报告三态 + 查询四态 + 建议版本）、快照不可变、命中排序（含平手）、身份证校验与加解密、BR-06 联动。
