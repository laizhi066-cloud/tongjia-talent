> 日期：2026-11-14　适用：`docs/天赋正式开发交接包/talent-prototype-v2/`（当前 `?v=1.51.9`）

## 1. 现状实测证据

同一屏两套判据（2026-11-14 实测，1440 × Chrome）：

| 孩子 | 后台查询状态 | 基因报告（geneReports） | C 端首页 | C 端报告页 |
| --- | --- | --- | --- | --- |
| 陈一凡 | 未查到（信息不一致） | ABC | **3 个分册可读** | 整理中、无正文 |
| 陈一宁 | 未查到（接口异常） | ACE | **3 个分册可读** | 整理中、无正文 |
| 陈一安 | 查询中 | A | **1 个分册可读** | 整理中、无正文 |

根因（都在 `pages-mini.js`）：

- `geneOf()`（第 150 行）读 `state.geneReports`，只要外部同步过就有篇目；
- `reportOf()`（第 156 行）只取 `status === '已发布'` 的 `state.reports`；
- 首页（249 / 284 行）与报告页页签计数（338 / 342 行）用 `geneOf().books`，正文用 `reportOf()`。

结果：**"有没有报告"与"能不能读"是两套数据**。撤回后首页仍显示"N 个分册可读"，报告页却打不开。

另：陈一诺名下有 3 条报告记录（`R20261104-001 已发布` / `R20261105-001 已撤回` / `R20261106-001 待发布`），与"一人一份"也不一致；C 端 `reportOf` 取数组第一份（最早），复测发布后仍展示旧报告。

## 2. 改动清单（4 处代码 + 1 处可选数据）

### 2.1 新增唯一判据 `reportView()`（`pages-mini.js`，约第 150 行后）

在 `reportOf` 上方插入一个 helper，把"取哪份报告 / 能不能读 / 能读几册"收成一处：

```js
/* C 端唯一报告判据：当前对象只有一份可读报告。
   已发布优先；同对象多份时按发布时间取最新（兼容历史演示数据）。
   可读性只看报告状态，不再用 geneReports 篇目推断。 */
function reportView(state) {
  const key = subjKey(state)
  const own = state.reports.filter(r => r.parentId === CURRENT_PARENT_ID
    && (r.subjectId === key || (key !== 'self' && r.childId === key)))
  const at = r => String(r.publishedAt || r.queriedAt || '')
  const pubs = own.filter(r => r.status === '已发布').sort((a, b) => at(b).localeCompare(at(a)))
  const report = pubs[0] || own.sort((a, b) => at(b).localeCompare(at(a)))[0] || null
  const status = !report ? 'none'
    : report.status === '已发布' ? 'read'
      : report.status === '已撤回' ? 'updating' : 'pending'
  const books = status === 'read'
    ? (report.volumeSnapshot || []).filter(v => v.open).map(v => v.id)
    : []
  return { report, status, books }
}
```

- 不改 `reportOf()`：它仍服务"要素快照 / 方向快照 / 已选方向"，语义就是"已发布的那份"，不要动，避免连带回归。
- 不改 `geneOf()`：它继续服务培育建议（建议与报告是两条同步链路，见 2.5）。

## 5. 改动量与风险

- 代码：新增 1 个 helper（约 15 行），改 4 个函数（首页 / 报告页 / 方向推荐 / 文案），合计约 60–80 行；不动 store 层。
- 风险点：
  1. 报告页页签计数改口径后，若客户习惯"6"表示基因报告总篇数而非可读篇数——验收时确认一下；建议"可读才计数"，与"撤回后不显示"一致。
  2. 0 命中回退后，推荐列表可能从 0 个变 6 个，需要确认"最多 5 个"的上限是否仍然生效（方案保留 `slice(0, recommendLimit)`）。
- 回滚：单文件 `pages-mini.js`，`git revert` 即可；无数据迁移。

## 6. 需要拍板的两个问题

1. **"没有匹配项"是否包括"整个对象没有任何报告"？**
   本方案按"有报告、但 0 命中"实现。若要求无报告也能选，需要给选择结果一个落点（挂到子女草稿档案），后台报告详情就看不到回流——属数据模型改动，不算最小变动。
2. **陈一诺名下 3 条报告记录是否收敛为 1 条？**
   默认不动（保留三态演示）。若要收敛，按 2.6 执行，同时更新 README 与待办数字。

另有一个观察项（不阻塞）：报告撤回后，培育建议仍会展示（建议是独立同步链路的"已发布"状态）。如果客户希望"报告不可读时建议也不显示"，在 `reportDetail()` 的建议分支加一句 `if (view.status !== 'read')` 即可，但会与第 2 条口径（建议按后台发布展示）产生交叉解释，建议先向客户确认。

## 8. 补充实施：没有报告也能选方向（本轮九十四）

客户在看到「报告未发布」时的方向页空态后追加口径：**没有匹配项也要能选培养方向**，本节按"包含完全没有报告"实施，替代第 6 节待确认项 1 的结论。

### 8.1 设计

选择结果需要落点，但不能伪造报告，因此新增一层轻量「方向意向」：

| 项 | 设计 |
| --- | --- |
| 存储 | `store.js` 新增 `state.directionIntents`，按测评对象 key（子女 id / `self`）存放，结构与报告 `selections` 一致 |
| 读取 | `selsOf()`：报告已发布读报告选择，否则读该对象意向；已选页签计数、取消、换档位、"自己填写"全部复用 |
| 写入 | `selectDirectionIntent()` / `removeDirectionIntent()` / `addManualDirectionIntent()`；上限仍为 `directionLimit`（3） |
| 回流 | `publishReport()` / `restoreReport()` 把意向并入报告 `selections` 并清空意向，后台报告详情立即可见 |
| 清理 | `restoreChildSeed()` 一并清空该对象意向 |

C 端展示：无报告时方向取自后台配置（命中记 0），卡片标「待报告」，顶部说明"报告发布后自动带入"；方向详情允许从配置取方向，档位回落当前档位配置，要素对照用潜质要素文库补名称与分级。

### 8.2 顺带修掉的串号 Bug

`app.js` 的 `firstReportId()` 原先在本对象没有已发布报告时回落到 `pubs[0]`（家长名下任意一份已发布报告），导致给二宝选方向会写进一宝的报告。现改为只认当前对象（`subjectId` / `childId`），没有就返回空、调用方改走意向层。

## 9. 修正（本轮九十五）：撤销第 8 节，建议与方向都以可读报告为前提

### 9.1 改法
