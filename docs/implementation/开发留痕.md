## 2026-09-24 计划匹配链路重构

- 正式项目新分支：`codex/talent-plan-rework-formal`。服务商即培养机构，培养计划直接绑定 `serviceInstitutionId`，新流程移除培训机构、课程和多计划共享入口；本项目不做旧流程兼容，schema、API、菜单和测试均按新模型维护。
- 代理商登记会员时可多选标准方向（认知能力、艺术、运动、表达沟通、综合发展），保存 `directionId`、`direction`、`category`、自定义原文和排序；培养偏好只影响计划推荐排序，不修改报告分级和固定注解。

## 2026-09-22｜PDF 私有存储与权限代理复核

- 复核发现原实现把 OSS/PocketBase PDF 原始地址直接返回给浏览器；这与“撤回、授权取消、机构停用、角色停用后 PDF 访问全部失效”冲突。
- 已改为：OSS 只保存私有对象并由服务端生成短期签名地址；新上传 PDF 还使用 `ENCRYPTION_KEY` 做 AES-256-GCM 加密，防止历史 public bucket 配置把可读 PDF 暴露出去；PocketBase `uploads` 中 `purpose=talent-report-pdf` 的文件禁止直链查看；数据库仅保存 `pdfFileKey`，第三方同步原始 `pdfUrl` 仅由服务端代理使用。
- 新增平台 PDF 权限代理 `GET /api/admin/talent/report/:id/pdf`；机构端和 C 端统一复用服务端读取适配器，响应前重新校验报告发布状态、开放分册、会员关系、服务商授权、机构和角色状态。
- 后台报告列表/详情、机构报告/会员详情不再下发 OSS/PocketBase 原始地址或存储 key；后台预览改为带当前登录态读取 Blob。
- 已执行 `pnpm talent:sync` 将本地 `uploads` 的 list/view rule 同步为 `purpose != "talent-report-pdf"`；旧报告仍由服务端按 `pdfFileKey` 读取，不依赖公开 URL。
- 真实本地 E2E `scripts/e2e/02-admin-actions.mjs`：平台代理读取 PDF、服务商授权范围读取 PDF、取消授权后 PDF 失效、底层 OSS 直链不返回可读 `%PDF` 均通过；旧版“公网可下载”断言已删除。
- 待生产联调：确认阿里云 bucket ACL/Policy 为私有，并在真实域名上复测签名读取、撤回和停用后的旧地址失效。

## 留痕中的冲突处理

- 样本、实验室、送检、物流不进入本项目；仅接收第三方结果和 PDF。
- “报告类型与分册”不作为菜单；内部模板集合仅用于匹配配置，旧菜单同步时停用。
- 付费只在发布弹框提示核实线下付费，不建设订单、续费或在线结算状态。
- 代理商只能登记/提交和查看自己引流会员的已发布报告；服务商只能查看授权会员并提交培养计划，**不能发布报告、不能管理授权**（本行早期版本曾写“服务商可在报告授权范围发布”，已作废）。
- 分册开放控制通过服务端 `talent_report_publications` 判权；旧条目无分册归属时，部分开放不会向 C 端返回，避免整份内容泄露。
