## 2. 角色与数据权限

| 角色 | 列表/详情 | 建档/编辑家长 | 子女编辑/解绑/查询 | 停用/启用 | 身份证全号 |
| --- | --- | --- | --- | --- | --- |
| 平台运营管理员 | ✅ | ✅ | ✅ | ✅ | ✅（独立权限 + 留痕） |
| 报告审核员 | ✅ 只读 | ❌ | ❌ | ❌ | ❌ 默认不授予 |
| 规则配置员 | ❌ 无菜单 | ❌ | ❌ | ❌ | ❌ |
| 家长（C 端） | 仅本人 + 已绑定子女 | ❌ | ❌ | ❌ | ❌ |

- 权限码（建议）：`talent:parent:list/view/add/edit/status`、`talent:parent:idno`（全号，独立）、`talent:child:edit/unbind/query`。旧 `talent:customer:*` 不复用、不改语义，M6 删除（同 M1 ADR-D5）。
- 每个权限码必须有 C/F 菜单行；接口侧 `requirePermission` 独立鉴权，前端隐藏不作数（CONVENTIONS §3）。
- 数据权限：家长只看本人 + 已绑定子女，服务端解析 parent 上下文，不接受前端传 `parentId`。
- **立即失效**：解绑或停用后，该对象从 bindings 消失，报告/建议/PDF 接口一律拒绝；不依赖缓存与 C 端本地状态。

## 3. 用户故事（后台）

1. **建档**：录入家长（姓名、手机号必填，身份证选填）+ 1–N 名子女（姓名、性别、亲属关系、出生日期、身份证必填），保存后按“家长手机号 + 子女身份证号”逐个发起查询。
2. **编辑子女**：详情“名下子女”就地展开面板；身份证不回显原脱敏值、留空即不改；保存后状态变“查询中”并就地刷新。
3. **主动查询**：对“未查到/查询中”点“重新查询”，回“查询中”，回执到达就地刷新（M2 用 Mock 异步回执）。
4. **解绑**：二次确认说明“家长端立即不可见、历史报告保留后台”，确认后关系失效、C 端同步不可见。
5. **家长侧契约**：登录拿“本人 + 名下子女”对象列表与当前对象，只含脱敏证件号、查询状态、报告可读状态；解绑/停用即刻消失。

## 4. 数据归属

**`talent_parents`（家长，一档一行）**：`parentNo`（唯一，列表首列）、`name` 必填；`mobileCipher/mobileHash/maskedMobile` 必填；`idNoCipher/idNoHash/maskedIdNo` 选填（家长身份证选填）；`gender/birthday` 选填；`source`（小程序注册/后台录入）、`status`（正常/停用）、`registeredAt` 必填；`userId` → `users`（登录账号绑定，Q3）；`remark` + `createdBy/updatedBy`。

**`talent_children`（子女，独立档案）**：`parentId` → `talent_parents`（解绑后置空，Q7）；`name/gender/birthday`、`relation`（父亲/母亲/祖父/祖母/外祖父/外祖母/其他监护人）必填；`idNoCipher/idNoHash/maskedIdNo` 必填；`query`（四态）、`queryReason`（三类归因，仅“未查到”有值）、`queryAt/queryAttempts`；`status`（正常/已解绑/已停用）、`unbindAt/unbindBy`；审计字段。

- 唯一键（建议）：`mobileHash` 唯一（一手机号一家长，冲突 409 引导合并）；`idNoHash` 全局唯一（一孩一档，解绑不删档、重绑复用）；`userId` 唯一且容忍空值（部分索引）。
- 旧模型对照：`childIds` / `childRelations` JSON → 子表 + 外键；`talent_customer_bindings` → `talent_parents.userId`。旧集合与旧页面保留到 M6，不删不改（同 M1 共存策略）。
- 加密脱敏：明文只来自请求体，服务端即时加密 + 哈希 + 脱敏后丢弃（复用 `crypto.ts` AES-256-GCM / `ENCRYPTION_KEY`）；列表、详情、子女表与 C 端一律只回脱敏值，**任何响应不回传 hash 或密文**（沿用 `sanitizeTalentAdminRecord` 口径）。
- 全号查看：独立权限 + 单项接口（不批量、不导出），每次写 `oper_logs`（操作人、对象、时间），日志不含明文。
- 证件校验：18 位 + 第 7–14 位与生日一致（BR-11）；新增子女必填、编辑留空不改；不合法 422。
- 已知缺口：现网只存 `idCardHash`（SHA-256 不可逆），旧数据无法支持全号查看 → 旧数据不迁移（Q1）。

## 5. 查询状态机与归因

```
未查询 --发起查询--> 查询中 --回执成功--> 已查到
                     查询中 --回执失败/超时--> 未查到(reason)
未查到 --重新查询--> 查询中
查询中 --再次重查--> 幂等，不重复发起（返回当前状态）
已查到 --编辑姓名/生日/身份证--> 自动 查询中
```

- **三类归因**：`信息不一致`（外部按手机号+身份证未匹配到检验人，运营核对资料）／`接口异常`（鉴权、超时、5xx，可重试）／`未出结果`（外部已受理未出结果，不算失败，等回执或定时重试）。
- **重查**：仅“未查到/查询中”给入口（PRD L179）；单子女最小间隔建议 ≥30s，重复点击幂等；编辑关键字段无条件重查；家长停用后不再发起新查询。
- **迟到/无归属回执必须丢弃**，不得生成或挂载数据（原型 `finishQuery` 已有守卫）。
- 重复查询不重复建档（BR-02）；建档归 M3，M2 只保证状态与回执归属。
- 工作台口径（M6）：注册家长 = parents 数；已出结果 = `已查到` 子女数；待出结果 = 其余，M2 状态枚举须能直接派生。
- **M2 用 Mock 适配器，不等 M8**：冻结 `TalentGeneQuerySource`（发起查询 / 回执）签名，Mock 可配成功/失败/未出结果/延时；真实重试、告警、限流归 M8。

## 7. B 端页面（`/admin/talent/member`）

1. **列表 8 列**（AC-ADM-02-1，一列一字段、无副行）：会员编号 / 家长（可点详情）/ 手机号（脱敏）/ 家长身份证（脱敏，空显示“未填写”）/ 名下子女（人数）/ 关联报告（份数）/ 账号状态 / 操作（详情为主 + 编辑 + 停用启用，Q9）。
2. **四项筛选交集**（AC-ADM-02-2）：家长姓名、手机号（完整或后四位）、子女姓名、账号状态（选项带数量）；变化回第 1 页，“重置”清空恢复全量。
3. **详情 ultra 弹层**：顶部信息条 + 三页签（带数量）——名下子女（子女/关系/身份证/查询状态含原因/关联报告份数/编辑·重查·解绑）；关联报告（编号/子女/状态/已选方向/目标档位/开放分册/查看报告，M3 未就绪为空态）；账号资料（编号、姓名、手机号、身份证、状态、来源、注册时间、子女数、报告数）。
4. **新建会员**（wide）：家长姓名、手机号必填，身份证选填；子女动态行 ≥1，每行姓名/性别/关系/生日/身份证；前后端双校验；保存后提示“N 名子女正在查询”。
5. **子女就地编辑**：与子女表格同弹层、不叠第二层弹窗；编辑态身份证为空 + 提示“原证件已脱敏，不修改请留空”（AC-ADM-02-4）；保存就刷新并高亮，状态变“查询中”（AC-ADM-02-3）。
6. **解绑二次确认**（AC-ADM-02-5）：说明影响 + “报告保留后台、可在操作日志追溯”；确认后列表与页签数量刷新。
7. 加载/空态/错误态齐全；空态可操作（“尚未绑定子女，新增后自动查询”“暂无报告”）；请求走新 composable，不直连 `useApi()`/PocketBase。
