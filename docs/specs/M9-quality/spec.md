### 1.3 硬约束

1. **不写代码**：本任务只允许改 `docs/specs/M9-quality/` 与 `docs/adr/`；不 commit。
2. **不把 P0 密钥写成已完成**：任何文档、证据表、STATUS 摘要都只能写「未修复 / 未验证 / 阻塞生产」。
3. **不恢复多租户/机构**：验收脚本与矩阵不得出现机构端、服务商、培养计划、内容库入口的「应存在」断言；只能断言其 `0 命中`。
4. **示例假数据**：家长「陈示例」/`13800000001`/`110101198001011234`，子女「陈小示」/`110101201609081234`，报告号 `GR202611160001`，建议号 `AD-GR202611160001-202611`；不得出现真实姓名、手机号、身份证、token、服务器地址与口令。
5. **质量门禁升级**：涉及 schema / 认证 / 权限 / 上传 / 跨端契约的验收按 [QUALITY](../../QUALITY.md) 的「schema / 认证 / 权限 / 上传」级执行，不得以「构建成功」代替。

### 1.4 术语与证据格式

| 术语 | 含义 |
| --- | --- |
| 冒烟套件 | 01–05，任何 B/C/API 改动后可跑，目标 ≤8 分钟，覆盖主链与权限边界 |
| 验收套件 | 06–10，发布门禁执行，逐 AC 取证，目标 ≤25 分钟，允许更重的数据准备 |
| 隔离实例 | 专用 `POCKETBASE_DATA_DIR`（`mktemp -d`）+ 专用 Nuxt/H5 端口；禁止指向开发演示库或生产 |
| 证据包 | `docs/specs/M9-quality/evidence/` 下的截图/JSON 摘要 + 表内命令与退出码；不得含 PII |
| 快照恢复 | 验收前 `pnpm backup:pb`，验收后恢复同一备份，使报告不可删除的副作用归零 |
| 记录人 | 执行验证的 agent/人；同一条证据只能由一个记录人签署 |

证据行最小格式：

```text
E-M9-<编号> | 对应 AC/门禁 | 命令或步骤 | 退出码 | 关键输出（≤3 行，脱敏） | 记录人 | 日期 | 结论
```

## 2. 验收唯一事实源与追溯规则

### 2.1 三层事实源

| 层 | 文件 | 作用 | 冲突时 |
| --- | --- | --- | --- |
| L1 需求 | PRD v1.1（尤其 §12） | 客户验收口径 | 以 PRD 为准；差异必须进入 §9 并由客户签字 |
| L2 模块 | `docs/specs/M1..M8/acceptance.md` | 模块级实现与证据 | 模块证据可被 M9 引用，但不能替代 M9 重新取证 |
| L3 发布 | 本文件 + [acceptance.md](acceptance.md) | 发布门禁与签字依据 | 以 L3 的通过判据为准 |

冲突处理顺序：源码与 `package.json` scripts（现状）→ PRD（需求）→ 本文件（发布合同）→ 模块 spec（实现合同）。发现 PRD 二义性时标 `待裁决`，不自行选一个口径。

### 2.2 追溯表列定义

| 列 | 要求 |
| --- | --- |
| ID | PRD 原编号（FR/AC/BR）或模块自定编号（AC-M4/M6/M8、AC-M9） |
| 验收要点 | 可判定的观察结果，不写「功能正常」 |
| 实现落点 | 文件/目录/接口；未实现写「规划」并标依赖 |
| 测试 / 证据 | 命令 + 套件 + 证据 ID；至少一条可复现路径 |
| 模块现状 | 引用模块 acceptance 的当前结论（已验收 / 有条件通过 / 实现中 / 未开始） |
| M9 状态 | 五值之一；初始全部 `未验证` |

### 2.3 通过判据

- 单个 AC：证据行齐全、关键输出符合验收要点、无 P0/P1 缺陷未关闭。
- 模块出口：该模块 AC 全部 `通过`，或 `不在范围` 有书面依据；`待裁决` 不得超过 2 条且已有客户/lead 裁决记录。
- 发布出口：G1–G10 全部通过（G9 仅生产发布必须通过；开发/测试发布可带 `P0 密钥未修复` 的书面豁免，但不得对外演示生产环境）。
- `未验证` 清零或逐条写「阻塞原因 + 依赖 + 解除条件 + 责任人」；不得用「部分通过」掩盖。

### 2.4 证据与账号

- 后台：`superAdmin`（全菜单）、平台运营 `admin`、报告审核员、规则配置员；口令只从 `SUPERADMIN_PASSWORD` / `CUSTOMER_ADMIN_PASSWORD` / 种子脚本环境变量读取。
- C 端：`talent-mock@example.com`（家长 + 两孩 + 有报告）、`talent-nochild@example.com`、`talent-noreport@example.com`；口令只从 `TALENT_MOCK_CLIENT_PASSWORD` 读取。
- 禁止在文档、截图、日志中记录真实 token、Cookie、密钥、服务器 IP/口令；截图必须使用虚构种子数据。
- 证据文件建议：`/tmp/tj-m9-*/`（临时，不提交）+ `docs/specs/M9-quality/evidence/`（脱敏后的汇总 JSON/截图）。

### 4.2 设计原则

1. **两层**：01–05 冒烟（快、稳、每次可跑）；06–10 验收（慢、逐 AC、发布门禁）。
2. **隔离**：验收套件只允许在隔离实例运行；`E2E_TARGET=remote` 仅允许 staging 且必须 `E2E_ALLOW_WRITE=1`；**生产域名一律拒绝**（`E2E_ALLOW_PROD` 不存在，硬失败）。
3. **可重复**：同一套件连续跑两次结果一致；所有创建数据带 `E2E-<suite>-<runId>` 后缀；能删的删、不能删的靠快照恢复。
4. **数据最小化**：仅在必要时写；优先用种子只读数据；写操作在 `finally` 清理；报告发布/撤回/补发用独立的临时对象。
5. **证据化**：每个套件输出 `{suite, runId, startedAt, checks:[{name,ok,detail}], passed, failed, durationMs}`；不含 PII/token。
6. **失败即非 0**：单条失败打印 `✗ 名称 期望/实际`，`run-all` 汇总后 `process.exit(1)`。
7. **不掩盖环境问题**：缺 Playwright / 缺服务 / 缺种子时明确失败并给复跑命令，不得 skip 后当通过。

### 4.6 数据准备、隔离与清理

1. **实例隔离**：验收使用独立 `POCKETBASE_DATA_DIR` + 独立 Nuxt/H5；启动前 `env:doctor`；禁止复用开发演示库；禁止 `pnpm deploy:remote` 指向生产。
2. **种子**：按 §4.5 顺序执行；每个 seed 脚本都有确认变量与生产硬拦截，不得绕过。
3. **跑前快照**：验收前 `pnpm backup:pb`（记录 backup key / 大小 / sha256），验收后恢复同一备份；替代「删除报告」。
4. **套件内清理**：创建即登记 `cleanup` 栈，`finally` 逆序删除；不能删的对象（报告/发布版本）记录 ID 并在恢复快照时消解。
5. **幂等验证**：06–10 每个套件末尾做一次「二次检查」：重复同一关键动作不新增行（报告 `refresh`、建议版本 `409 noop`、绑定幂等）。
6. **临时目录处理**：确认路径为 `mktemp` 生成目录后再删除；不得删除 `pb_data/`、项目根目录或未明确定位的路径。

### 4.7 失败处理与证据

- 单条失败：`✗ 名称` + 期望/实际 + 请求/页面 URL（脱敏）；立即继续跑完余下断言，最后汇总。
- 环境失败：缺 Playwright / 服务不可达 / 种子缺失 → 套件开头 fail-fast，退出码 2，提示复跑命令。
- 证据：`summary.json` + 失败明细 + 关键截图（Playwright 失败自动截图）；不得包含 token、Cookie、PII。
- 连续两次失败同一断言 → 按缺陷分级登记；不得通过放宽断言或改 seed 掩盖。

### 5.3 测量方法

1. **环境固定**：同一台机器、同一提交、同一数据集；服务 `127.0.0.1`；关闭无关进程；记录 CPU/内存/Node/PB 版本。
2. **预热**：每个指标先跑 3 次丢弃；再取 10 个样本。
3. **统计**：中位数与 p95；API 用 `curl -w '%{time_total}'`（10 次），页面用 Playwright `performance.getEntriesByType('navigation')` 或首屏元素可见时间；PDF/同步用服务端日志耗时。
4. **冷热分离**：PDF/页面明确冷启动（清缓存/重启后首次）与热缓存（第二次）分别记录。
5. **对照**：同数据集下对比上一版本；退化 >20% 视为回归，即使未超门槛也要记录并评估。
6. **记录格式**：

```text

```

7. **禁止**：为达标删数据、改分页大小、关闭鉴权、缓存整页冒充首屏、只测空库。数据量、分页参数、筛选条件必须写进证据。

补充判据：

- 403 只用于「有身份但无权限」；越权对象统一 404，避免泄露存在性；C 端账号停用 403 `ACCOUNT_DISABLED`。
- 所有写接口先鉴权后写日志；无权限请求不得产生成功 `oper_logs`。
- 三角色矩阵按 [M6 spec](../M6-cleanup/spec.md) §6.3/§6.4 精确断言（工作台拆码：规则配置 `GET /dashboard` 200、`GET /reports` 403）。

### 6.2 脱敏、全号与日志

| 项 | 规则 | 验证 |
| --- | --- | --- |
| 列表/详情/导出 | 手机号、身份证只返回脱敏值（前 4 + 后 4）；响应不含 `*Cipher` / `*Hash` / 明文 | E2E 06/08/10：递归扫描响应键与值；导出 CSV 同样脱敏 |
| 全号查看 | 仅 `talent:parent:idno`；单独接口；每次写 `oper_logs`；日志摘要不含明文 | E2E 06：无权限 403 且无成功日志；有权限 200 + 日志 1 条；日志正则无 11/18 位数字 |
| 数据库落盘 | 手机号/身份证密文 + HMAC + 脱敏三件套；PDF/建议正文不含证件号 | E2E 06：PB 直查无明文；错误 key 不解密 |
| 审计日志 | 摘要只含业务编号/名称/动作；无手机号、证件、正文、附件地址 | 日志扫描：`rg -nE '\b1[3-9][0-9]{9}\b\|\b[0-9]{17}[0-9Xx]\b'` 对证据日志 0 命中（允许白名单虚构示例号） |
| 前端令牌 | token 仅在内存/localStorage 受控 key；不写 URL、不写日志、不进构建变量 | E2E 10：页面 URL/console/网络请求无 token；`.output` grep 密钥 0 命中 |

## 7. 可观测性

| 观测项 | 方式 | 阈值 / 告警 | 证据 |
| --- | --- | --- | --- |
| 应用存活 | `GET /api/health` | 非 200 连续 2 次 → P1 | E2E/发布后探活 |
| 应用 + DB | `GET /api/health?deep=1` | `degraded` 连续 2 次 → P1；PB 不可达 → P0 | 发布清单 |
| 5xx / 错误率 | 进程日志 + 错误监控 | 5 分钟 >1% 或 >10 条 → P1 | 发布后 2 小时观察 |
| 接口延迟 | 访问日志/采样 | 列表 p95 >2.5s → P2；持续 3 个窗口 → P1 | 性能证据 |
| 同步失败 | `talent_sync_logs` + 告警钩子 | 连续 3 次失败 / 无成功超 2×间隔 → P1 | E2E 03/07 |
| PDF 失败 | 代理日志 + `talent_pdf_downloads` | 10 分钟失败 >5 次 → P2 | E2E 10 |
| 登录失败 | 登录日志 | 同账号 10 分钟 >10 次 → P2（防爆破） | 安全回归 |
| 磁盘 / 备份 | 进程/系统监控 | 使用率 >80% → P1；备份失败 → P1 | 运维周检 |
| 审计可查 | 操作日志/登录日志/错误监控 | 关键动作缺失 → P1 | AC-ADM-08-2/3 |

- 日志：应用与 PB 日志轮转（`pm2-logrotate`/logrotate），保留 ≥14 天；业务日志保留按合规要求（≥180 天建议）。
- 告警通道：通用 webhook（企业微信/飞书）+ `error_logs` 兜底；通道地址只在服务端环境变量，不写文档。
- 观测不得记录 PII：日志中手机号/证件只在必要处脱敏，禁止记录 token、Cookie、完整请求体。

## 8. 备份、回滚与发布门禁

### 8.1 备份与恢复

| 项 | 要求 |
| --- | --- |
| 日常 | 每日 03:00 `pnpm backup:pb`；保留 ≥14 份；同步异地/对象存储 |
| 发布前 | 涉及 schema/权限/高风险接口时，在**目标环境**做一致性备份并记录 key/大小/sha256 |
| 恢复演练 | 每季度一次 + M6 前必做；在隔离目录恢复，验证集合数/关键行数/登录/列表/C 端 |
| RPO / RTO | 日常 RPO ≤24h；发布窗口停写后 RPO≈0；单机 RTO ≤30 分钟（按 OPERATIONS） |
| 禁止 | 运行中直接复制 SQLite 目录作为唯一备份；用 `env:setup` 覆盖存量库；生产执行 `talent:seed` |

### 8.2 回滚

| 变更类型 | 代码回滚 | 数据回滚 | 备注 |
| --- | --- | --- | --- |
| 纯前端/文案 | 切上一稳定 tag + `deploy:remote -- --no-db` | 不需要 | 先回代码 |
| 新增集合/字段（只加不删） | 同上 | 不回滚 schema；旧代码不读新集合 | 兼容 |
| M6 破坏性清理 | 切 `pre-m6-cleanup-<date>` tag | **整库恢复**备份，禁止局部补集合 | 先恢复数据再启旧代码 |
| M8 外部源/PDF | 关 PDF → 关调度 → 切 mock/关入站 → 代码 | 不回滚已同步数据；新增集合保留 | 按 M8 §14 顺序 |
| 数据损坏 | 先停写、保留证据 | 最近可用备份整库恢复 | 记录 RPO 缺口 |

回滚验证：`GET /api/health?deep=1` 200；后台登录；会员/报告列表；C 端报告页；`talent_sync_logs` 不再新增异常；错误率回落。禁止 `git reset --hard`、删除 `pb_data/`、删集合「修复」。

### 8.3 灰度（单实例下的替代做法）

单实例不允许 PM2 cluster 双版本；「灰度」采用：

1. 预发/隔离环境先跑 01–10 + 性能 + 安全；
2. 低峰窗口发布（`--no-db`）；发布前备份；
3. 功能开关：M8 外部源/PDF/调度可关；M6 清理不可灰度（一次性整库恢复）；
4. 发布后 30 分钟观察 + 关键路径冒烟（01/04/05）+ 2 小时观察 5xx/延迟；
5. 触发条件即回滚（见 8.2），不「带病观察」。

## 11. 缺陷分级（P0–P3）

| 级别 | 定义 | 示例 | 发布影响 | 处置时限（建议） |
| --- | --- | --- | --- | --- |
