# 天赋计划重梳理设计

日期：2026-09-23
状态：开发基线，供正式项目与原型同步

## 目标

把培养计划、要素解读和报告发布的职责边界收紧，消除原型中多选及服务商发布报告造成的歧义。现有报价三端范围不变，检测系统仍只提供第三方结果。

## 冻结业务规则

### 要素注解链路

生成要素解读必须按“检测结果 → 后台分级 → 固定注解 → 年龄/性别条件 → 培养内容”顺序执行。每个命中项记录结果值、分级、注解、条件、内容和规则版本；缺分级、注解或内容时生成缺口并停在待补齐/待审核，AI 只能给建议。已发布内容使用快照，规则更新不得悄悄改写历史。

### 培养计划审核

计划由平台或服务商维护草稿，提交后进入平台待审核；平台通过后才允许上架、进入推荐池和被客户选择。退回必须写原因，原提交方修改后重新提交。计划必须绑定一个有效服务商；服务商本身就是培训服务主体，不建立独立培训机构或课程对象。

### 单选推送与授权

C 端从有效推荐中选择一个培养计划及其负责服务商，核对拟共享资料和已发布报告后确认。后端以会员、计划、服务商为幂等键建立一条授权并推送；重复提交只返回现有授权或重试通知。计划查看不等于授权，取消后重新选择必须重新确认。

### 报告发布职责

平台负责检测报告审核、开放分册、发布和整份撤回。服务商不提供报告发布入口或权限，仅在授权范围内只读查看已发布内容并做线下跟进。

## 范围与非目标

保留原有三端报价、第三方结果接收、报告/解读分离、AI 人工审核和权限复核。不新增支付、课程商城、排课、在线签约、实验室或任意 PDF/OCR；不改变后端接口约定之外的检测结果含义。

## 验收场景

1. 缺固定注解时报告显示缺口且不能发布；补齐后可重新生成并看到命中快照。
2. 计划退回、修改、重提、审核、上架链路完整，未审核计划不能被选择。
3. C 端最多存在一条当前选择；重复点击不产生第二条授权，推送失败可重试。
4. 服务商没有发布报告动作，只能读取授权且已发布报告。
5. 撤回、取消授权、停用机构或计划后，详情、导出和 PDF 访问重新判权。
