**同一时刻只呈现一个对象**：报告中心、首页提示条、要素目录与阅读进度全部以当前测评对象为范围，不在同一屏混排多个孩子的记录；切换对象后整屏内容随之替换。据此，记录只有一条时不出现状态筛选——多数家长只有一位孩子、一份报告，C 端不为个例堆控件。

  - `解绑` 增加二次确认，说明家长端不可见、已有报告保留在后台、操作可追溯；确认后回到详情。
- **关联报告页签**：按子女归属列出方向、档位与快照版本，`查看报告` 直达报告详情，避免与列表上的重复入口。
- **数据建模结论**：子女用**独立子表 + `parentId` 外键**（原型 `state.children` 即此形态），不放在家长记录里做 `children` 数组 / 嵌套 JSON；界面也不用主表树形 `children` 展开行。理由：查询状态、报告、108 项要素结果、证件唯一性都挂在子女上；一个子女未来可能被父母两个账号共同查看；独立表才能建唯一索引、按子女分页检索、单独更新查询回执。正式开发建议再拆一层关系表：`talent_child`（子女档案，证件号唯一）+ `parent_child`（归属关系、是否主监护人、绑定 / 解绑状态与时间），报告外键指向 `child_id`；若客户明确「一孩只属一户」，可先沿用单外键，但字段命名要留出演进空间。

**家长身份证号为选填**：新建与编辑表单均可留空；填写时校验 18 位格式，保存后按脱敏值存储；未填写显示「未填写」。子女身份证必填，用于主动查询，并校验与出生日期一致。`新建会员` 弹窗在同一表单内录入家长资料与多名子女，子女行可添加 / 移除；保存后逐个触发主动查询。

**仍待正式实现补齐**：原型沿用主动查询模拟逻辑，每次编辑保存 / 重新查询都会为该子女生成一份新报告草稿；正式实现需按 `child_id + 检测批次` 做幂等，只更新查询状态与结果，不重复建草稿。

### 报告阅读：108 项要素的分类筛选

- **数据源是报告快照**：每份报告保存 `factorSnapshot`（发布时冻结的 108 项要素：编码、名称、分类、得分、分级、命中固定注解、年龄/性别条件）。后台后续修改要素名或固定注解，已发布报告不变；**重新发布**才按当前规则重新冻结。后台「报告详情 → 基因报告」读的也是这份数据。
- **固定六册**：报告按 6 个分类组织为 6 个分册，发布时在弹层中逐册勾选开放范围，写入 `volumeSnapshot`（册名、分类、章节、章节内要素、开放状态）。家长端「报告总览 → 报告分册 → 分册章节」逐层查看，未开放分册不可进入；要素目录与筛选也只覆盖已开放分册内的要素。
- **搜索 + 筛选遮罩**：要素目录默认只有搜索框（内置放大镜图标，回车即搜）与一个筛选图标；分类（6 类）与分级（卓越 / 优秀 / 优良 / 常态）收在底部遮罩里单选，点「确定」关闭。已选条件以标签回显，点标签即可清除；不设搜索按钮与重置按钮。
- **头部快速切换**：要素详情页头部是两级切换条——第一行 6 个分类（当前分类带短横线），第二行该分类下的 18 项要素标签，点标签直接跳到该项；切换条随滚动吸顶，两端渐隐提示可横滑，进入时自动把当前项滚到可视区中间。
- **可看全 108 项**：首屏 20 项，点击「加载更多（还有 N 项）」逐批加载，列表顶部显示「共 N 项 · 已读 X / 总数」。
- **阅读闭环（仅 C 端）**：点击要素进入详情（得分大字、分级、**天赋解读**、适用条件、关联培养方向），按要素编码写入 `readCodes`，目录以绿点与浅色标题标记已读，`阅读进度 = 已读要素数`；上一项/下一项与「第 N / 18 项」限定在当前分类内循环，与头部标签一一对应；已读进度按全报告 108 项统计。**2026-11-11 起后台不再展示阅读进度 / 阅读记录**，C 端进度仅作家长自己的阅读提示，不作为后台运营指标。
- **可见性**：仅已发布、且测评对象仍归属当前家长的报告可进入详情；待发布、已撤回、家长账号停用、子女解绑后，C 端同步不可进入（待发布与撤回在报告中心以状态卡展示）。
- **多状态演示**：当前家长下 4 名子女分别演示「已出结果（多份记录）」「信息不一致」「接口异常」「查询中」四种情形；状态胶囊带数量并可筛选，记录只有一条时不显示胶囊，未出结果可「核对信息」或「重新查询」。三种未出原因在 C 端一律转成家长语言，不出现「接口异常」等技术表述。
- **术语去后台化**：家长端统一使用「天赋解读」「培养方向」「目标档位」「报告分册」；快照版本、命中率、方向版本、固定注解等词只出现在后台。

## 九、运行

```bash
cd docs/天赋正式开发交接包/talent-prototype-v2
python3 serve.py 8901          # 静态托管 + 所有响应 no-store，刷新即见最新
# 浏览器打开 http://127.0.0.1:8901/index.html
# 改动任意 js/css 后：python3 bump-version.py 1.22.0
```

纯静态 HTML + ES Modules，无构建、无后端。交互状态保存在浏览器 localStorage，点击顶栏「重置数据」可恢复初始状态。资源版本当前 `?v=1.61.0`。

**缓存约定**：不要用 `python3 -m http.server` 代替 `serve.py`。前者只返回 `Last-Modified`，浏览器会启发式缓存 JS；且 `index.html` 的版本号只覆盖入口文件，`app.js` 内部的 `import './pages-mini.js'` 若不带 `?v=`，改动就不会生效（曾导致「代码已改、页面仍是旧文案」）。因此每轮改动后用 `bump-version.py` 统一刷新 `index.html` 与全部 14 处模块 import 的版本号。

**三端入口**（同一个 `index.html`，顶栏可互相切换）：

| 入口 | 地址 | 说明 |
| --- | --- | --- |
| **登录页（演示入口）** | `http://127.0.0.1:8901/index.html?view=login` | **打开即小程序登录页**，勾选协议后「微信一键登录」进首页；强制清除本机残留登录态，反复打开 / 刷新都回到登录页 |

`?view=login` 是**专供发给客户 / 演示用的登录直达链接**：无论访客此前是否登录过，都会回到微信一键登录页，协议勾选态也会重置。参数只在首次进入生效，随后从地址栏移除、落地 hash 写成 `#/mini/login`。不带参数的根地址仍默认进后台管理，不影响原有演示路径。

C 端以手机模拟器形式呈现，含登录、首页 / 报告 / 我的 3 个 tab，以及报告总览、报告分册、分册章节、要素目录、要素详情、培养方向列表、方向详情、目标档位、已选方向、自定义方向、测评对象选择、编辑资料、子女管理、协议与隐私政策等二级页；**是网页交互原型，不是微信小程序工程**。默认打开 `index.html` 时若直接点顶栏「小程序端」，会先看到登录页，需点「微信授权登录」进入；用 `?view=mini` 可跳过这一步。直达参数首次进入后自动从地址栏移除，切到后台后刷新不会被拉回 C 端。

## 十、业务链路操作顺序

1. **规则同步**：外部系统按「性别 + 具体年龄」推送潜质要素文库，后台「潜质要素」只同步与查看；「分级与固定注解」维护分级设置与固定注解，可各自页内导入。
2. **方向与档位配置**：后台「培养方向管理」单表配置方向、要素与要求分级；在「档位维护」中编辑默认四档（系统固定四档，不再新增）。
3. **建档与查询**：后台「会员管理」新建会员并录入子女（家长身份证选填），或切到小程序端由家长注册并添加子女；保存后系统按手机号 + 身份证号主动查询。
4. **报告同步与发布**：外部基因检测系统按台账身份证号返回基因报告，后台「基因报告」点「一键同步全部报告」批量拉取（已有报告的刷新同步时间、缺报告的按身份证号建档、外部无数据的跳过）；再查看待发布报告，点击「发布」→ 勾选本次开放的六册 → 预览方向命中项数 → 确认后生成方向命中结果与分册快照。
5. **阅读与选择**：小程序端首页 → 报告中心（按测评对象筛选状态，点击可查看报告）→ 总览（此处才出现分册、培养方向与目标档位）→ 报告分册 / 分册章节，或分类快选进入要素目录（分类/分级/关键词筛选、加载更多、逐项阅读）→ 单项详情 → 培养方向列表 → 方向详情 → 目标档位 → 确认 → 已选（≤3）。首页对象条或顶栏「切换」可切换本人 / 子女，选择后回到来源页。
6. **数据回流与快照核对**：后台「基因报告」查看已选培养方向和目标、匹配天赋（发布时 vs 当前配置）、培育建议；「会员管理 → 关联报告」按家长维度回看同一份数据。如需按新配置计算，在报告详情执行「按当前配置重新生成快照」。

「业务流程」页把 5 阶段 12 环节逐一对应到可点击位置，含输入、输出、执行方与关键校验。

## 十一、关键口径

- **主动查询**：绑定即查 + 定时重试 + 手动补查；未查到按未出结果 / 信息不一致 / 接口异常三类归因。
- **测评对象**：家长本人为固定选项，名下子女可切换；报告按 `subjectType / subjectId` 归属，切换后首页统计、报告中心与报告总览同步变化。名下无子女时不显示切换入口。家长在「我的 → 编辑」维护姓名、手机号、性别、出生日期与选填身份证号，后台会员列表同步。
- **报告是快照**：发布即冻结 108 项要素结果 / 分级 / 注解、固定六册的开放范围，以及方向、档位与方向命中结果；后续调整任何配置都不影响已发布报告。重新发布或对指定报告显式「重新生成快照」才按当前配置重算，两者都写操作日志。
- **六册开放**：报告固定 6 册（按分类划分），发布弹层逐册选择开放范围；家长端只能看到已开放分册的章节与要素，未开放分册在目录中标为「未开放」。
- **方向命中**：报告要素实际分级级序 ≥ 方向要求分级级序即记 1 条命中；按命中条数降序展示，同命中数依次比较命中率、配置条数、方向编码。家长端只展示命中 ≥ 1 的方向，最多 5 个；不再计算权重与匹配度。自定义方向不参与推荐：家长在「选择方向」页的方向下拉里，可直接选后台已配置的方向（按报告快照），也可选「其他」自己填写，名称限 10 个字；培养目标从四个目标档位中显式选择，不再固定取默认档位。
- **档位**：默认四档并支持自定义新增、编辑、停用与设置全局默认值；家长选择时档位必选，按方向默认档位预选。
- **数据闭环，不是业务闭环**：系统内配置、查询、生成、发布、阅读、选择、回流全部有数据落点；选完方向后的联系、排师与成交在线下，不属于本期系统范围。
- **身份证合规**：子女身份证单独授权、哈希匹配 + 明文加密存储；家长身份证选填且同样脱敏；前后台默认只显后 4 位，后台看全号需独立权限并留痕。

### 已确认口径与实施边界

1. **六分册与发布快照**：客户已确认保留 6 分册，并确认方向命中结果在发布时生成快照、后续配置调整不影响历史报告；原型与报价单均按此实现，不再作为待决策项。
2. **定时重试与真实接口**：原型用异步回调模拟主动查询与重试，「查询重试次数」等参数为配置占位；正式实现需要真实第三方接口、重试队列、幂等键与失败告警。
3. **六册来源**：原型以 6 个分类作为固定六册并生成章节；正式联调时需确认第三方返回的六册编号、册名与章节结构，以及 PDF 是整份还是按分册提供。
4. **原型形态**：当前是网页手机模拟器原型，不是微信开发者工具可直接运行的小程序工程；快照目前存浏览器本地状态，正式实现需落库并加权限校验。
