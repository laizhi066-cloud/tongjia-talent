日期：2026-09-23

## 1. 文档与原型基线

- 更新 `talent-prototype/README.md` 与交接包 README，标注单选推送、审核和平台发布职责。
- 更新启动文案、功能清单顶部的冻结规则；保留报价原始行号，不删除历史条目。
- 更新两份 Mermaid 源图及流程节点文案；PNG/SVG 已由 Mermaid 源生成；zip/hash 待代码合并后统一处理。

## 2. 领域与接口调整

- 在计划选择命令中使用单一 `planId`、`providerId`，以 `memberId + planId + providerId` 做幂等校验。
- 授权状态保留待确认、已授权、已取消、推送失败/重试；通知重试不得重复授权。
- 报告发布动作仅保留平台角色；服务商查询接口只返回已授权且已发布数据。
- 生成解读时写入分级、固定注解、年龄/性别条件、培养内容和规则版本快照。

## 3. 页面与权限

- C 端把计划/服务商选择器改为单选，确认页展示共享范围和负责服务商。
- 平台保留计划待审核页签、审核退回原因、发布/撤回入口及命中明细。
- 服务商计划库只维护绑定本服务商的计划；服务商会员/报告页去除发布按钮，保留授权范围只读查看。
- 不新增培训机构与课程对象、菜单、接口或权限。

## 4. 验证顺序

1. 先跑文档与原型静态检查，确认流程源无“多选计划/服务商发布报告”的当前口径。
2. 执行单选授权幂等、计划审核、要素注解缺口、平台发布权限和撤回判权测试。
3. 浏览器验证 C 端单选、确认/失败重试，以及服务商无发布动作；再做桌面/移动端回归。
4. 代码合并后生成 PNG/SVG、交接 zip 与 SHA-256，更新资料清单和开发留痕。

## 5. 完成标准

- 设计规则、启动文案、功能清单、README、流程源一致。
- 单选授权与推送在刷新、重复提交和失败重试下保持幂等。
- 要素解读链路和计划审核有可追溯记录；报告发布权限没有泄露给服务商。
- 全量源码测试、构建和浏览器验证由代码实施者完成并在交接包记录证据。
