# tongjia-talent 项目长期笔记（换机续接锚点）

## 项目与仓库
- 同佳天赋专项：报价 / 合同 / 交接资料 + 可交互原型 `talent-prototype-v2`（管理后台 + 小程序 C 端）。
- 分支 `codex/talent-plan-rework-formal`，远端 Gitee 私有仓库 `tongjia_jiankan/tongjia-talent.git`。
- 原型路径：`docs/天赋正式开发交接包/talent-prototype-v2/`；纯静态 HTML + ES Modules + localStorage，无构建、无后端。
- 临时验证脚本一律放 `/tmp/t_*.cjs`，跑完删掉，不留在仓库。
- 换机注意：`.env` 已入库且含 OSS AK/SK 明文，`POCKETBASE_BINARY` / `POCKETBASE_DATA_DIR` 写的是本机绝对路径，新电脑需改路径并评估轮换密钥。

## 原型运行（踩过坑，务必照做）
- 用 `python3 serve.py 8901`，**不能**再用 `python3 -m http.server`（不发 `Cache-Control`，浏览器启发式缓存旧 JS，曾出现「代码改了页面没变」）。
- 每次改 js/css 后必须跑 `python3 bump-version.py <新版本>`：统一刷新 `index.html` 与全部模块 import 的 `?v=`，否则旧缓存不失效。当前 `?v=1.25.1`。
- 入口：根地址＝后台；`?view=mini`＝已登录小程序首页；`?view=login`＝强制登录页；`?view=flow`＝业务流程图。所有链接仅本机 `127.0.0.1:8901` 可访问，未做对外发布。

## 关键业务与数据决策
- 子女用独立 `children` 表 + `parentId`，不嵌在会员对象里；会员管理列表只做定位，详情弹层统一管家长 / 子女 / 报告。
- `children.relation`（与家长关系）：父亲/母亲/祖父/祖母/外祖父/外祖母/其他监护人，常量在 `demo-data.js`，C 端与后台共用。
- 报告发布走快照冻结：`factorSnapshot` / `directionMatch` / `volumeSnapshot` / `snapshotVersion`；支持 `restoreReport(id)` 撤回后恢复。
- 下载：`state.downloads`、`buildDownloadFiles`、`recordDownload`，6 册独立 PDF、水印、7 天有效期、后台留痕。
- C 端单对象原则：只展示当前测评对象，一孩一报告不出现筛选；内部技术词（如「接口异常」）不得出现在家长端。
- 口径差异（**勿误改**）：C 端「已撤回」统一显示为「更新中 / 报告内容更新中，完成后即可查看」，后台与数据层仍保留 `status='已撤回'` 及恢复发布；后台已下线「阅读进度 / 阅读记录 / 有效期设备」，C 端已读进度条与下载有效期文案仍保留（用户明确「只清后台」）。

- **培育建议最终口径（2026-11-12 三次纠偏后，勿再回退）**：业务流 = 基因检测报告（每人一份、固定格式、外部系统同步，A~F 六篇按人子集，实测 156 项专项潜质，「数据熵」= 卓越/优秀/常态/弱态四级）→ 根据基因报告输出**一份培育建议**（一份对一份，按「姓名 + 年龄段」匹配）→ 家长根据建议选培养方向。**本系统只同步、更新、展示，不生成 / 编辑 / 发布任何报告与建议内容**。状态层为 `geneReports / adviceDocs / adviceVersions / currentAdviceVersionId / syncLogs`（4 个月一版，旧版归档、版本历史只读可回溯）；后台培养建议页 = 同步清单 + 版本条 + 同步日志；C 端一页一份建议书（按篇目分组、四段家长视角、无后台词），看完引导选方向。旧 `suggestions` 文库模型已全部删除。
- 客户《天赋培育开发建议文库数据库（男0岁）》是外部系统匹配建议时用的素材库（158 要素 × 4 级 × 3 变体 = 1896 槽位、仅 27 条填充），不是本系统维护对象；未全量导入，女童 / 其它年龄切片是另建同结构文件。正式版建议把「0 岁男婴」类硬编码改为按孩子性别/年龄渲染的占位符。
